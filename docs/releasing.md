# Releasing

`tmux-connect` publishes GitHub releases from version tags that match `v*`.

## Standard Flow

1. Land the release-ready changes on `main`.
2. Create and push an annotated tag such as `v0.2.0`.
3. Let `.github/workflows/release.yml` build the release artifacts and publish the GitHub release.

The release workflow currently publishes:

- `linux/amd64`
- `darwin/amd64`
- `darwin/arm64`

Each release also includes `checksums.txt`.

## Release Notes

Release notes are built from two parts:

- A repository template in `.github/release-notes.md.tmpl`
- GitHub autogenerated release notes appended below the template

The template gives every release a stable structure:

- project summary
- highlights
- shipped assets
- getting started links
- current limits

If a release needs special handling, edit the published GitHub release and add:

- breaking changes
- upgrade notes
- migration steps
- connector-specific caveats

## Re-running a Release

If a tag already exists and you need to re-run packaging or publishing, use the `release` workflow's `workflow_dispatch` entry and pass the existing tag name.

That path is intended for cases like:

- runner label fixes
- release note template changes
- packaging corrections
